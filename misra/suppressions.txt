# --- Cortex-M/CMSIS memory-mapped I/O (structural, not a code defect) ---
# GPIOB/GPIOC/GPIOG/LPUART1/TIM6/... are CMSIS device-header macros that
# expand to a pointer cast of a fixed peripheral base address (e.g.
# `#define GPIOB ((GPIO_TypeDef*)GPIOB_BASE)` in Drivers/CMSIS, which is
# itself excluded via exclude-paths.txt). cppcheck attributes the finding
# to the call site where the macro is *used* (HAL_GPIO_Init, __HAL_RCC_*,
# hlpuart1.Instance = LPUART1, htim->Instance == TIM6, ...), not to the
# macro's own definition -- there is no way to touch a peripheral register
# in C without this exact pointer-from-integer construction, and it
# recurs on nearly every HAL call in every STM32 project. Industry-standard
# handling is a project-level MISRA deviation for register access, not
# rewriting away from the vendor HAL.
