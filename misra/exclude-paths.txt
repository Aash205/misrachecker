# Glob patterns (bash [[ == ]] matching) for paths fully excluded from both
# lint engines. Vendor/generated code is never hand-edited, so linting it
# just adds noise and false "violations" in code we don't control.
*/generated/*
# All of Drivers/ is vendor (HAL_Driver, CMSIS, and any BSP layer CubeMX
# drops in there, e.g. Drivers/BSP/STM32L4xx_Nucleo_144/ -- pulled in whole,
# never linked into .project, never hand-edited). A prior narrower pattern
# (*/Drivers/*HAL_Driver/* + */CMSIS/*) missed BSP entirely; broadened to
# match what .pre-commit-config.yaml and the README already document
# Drivers/ as: vendor, full stop.
*/Drivers/*
*/Middlewares/*

# ARM cross-toolchain's own system headers (newlib libc, GCC builtins,
# libstdc++) -- reached when gen_compile_flags.sh finds a real
# arm-none-eabi-g++ on PATH and cppcheck actually resolves its -isystem
# paths (verified: without a real cross-compiler on PATH, compile_flags.txt
# only carries -mcpu/-mthumb and these paths never resolve, so this was
# never a live risk until that fallback started finding a real toolchain).
# Not our code, not even ST's -- upstream newlib/GCC, never hand-edited.
*/arm-none-eabi/*

# CubeIDE-generated runtime stubs living directly under Core/Src (not caught
# by the Drivers/CMSIS/Middlewares globs above since they sit next to
# hand-written project code) -- weak POSIX hooks (_sbrk, _write, _kill, ...)
# and clock-init boilerplate ST templates out for every target, never
# hand-edited, same "not our code" rationale as the vendor dirs above.
*/syscalls.c
*/sysmem.c
*/system_stm32*.c

# CubeMX/CubeIDE skeleton files that are near-100% generated (interrupt
# vector stubs, MSP init, HAL timebase override) -- USER CODE markers exist
# in these too, but in practice almost nothing is ever added there.
# main.c and freertos.c are deliberately NOT listed here: real init/task
# logic lives in their USER CODE blocks, so MISRA findings in hand-written
# code there should stay visible.
*/stm32*_it.c
*/*_hal_msp.c
*/*_timebase_tim.c
# Matching headers for the above -- interrupt-handler prototypes only, no logic.
*/stm32*_it.h

# CubeMX-template config headers -- HAL module enable/disable and FreeRTOS
# tuning knobs are technically user-editable, but the surrounding file is
# CubeMX-regenerated boilerplate and its own MISRA findings (function-like
# config macros, ST/FreeRTOS header patterns) are template noise, not
# project logic.
*/stm32*_hal_conf.h
*/FreeRTOSConfig.h

# Core/Startup: reset handler + vector table (.s) and linker script (.ld),
# 100% CubeMX-generated, never hand-edited (verified against ST's own
# project layout: Core/{Inc,Src,Startup}, Drivers/{CMSIS,*_HAL_Driver},
# Middlewares/ -- https://www.st.com/resource/en/user_manual/um2388-...).
# lint.sh only ever collects .c/.cpp/.hpp today so this folder was never
# actually a live risk, but excluded explicitly so it stays inert if the
# collected extensions ever change or someone lints this path directly.
*/Core/Startup/*

# Non-firmware dirs that can end up under the repo root (Python venvs used
# to bootstrap pre-commit, VCS internals, build output) -- these aren't
# project source, but format.sh/lint.sh default to scanning the whole repo
# when no target is given, so they get swept in unless excluded explicitly.
*/.venv/*
*/venv/*
*/.git/*
*/Debug/*
*/Release/*
*/.metadata/*
*/node_modules/*

# demo/ holds deliberate MISRA violations for the self-test walkthrough
# (see README) -- never gate commits/CI on them. The misra-lint pre-commit
# hook also excludes demo/ via its own `exclude:` regex, but that only
# stops demo/ files from being passed as argv; since the hook runs with
# pass_filenames: false (cross-TU correctness needs the whole target
# scanned together, not just staged files) and lint.sh's own whole-repo
# scan doesn't know about pre-commit's regex, this pattern is what
# actually keeps demo/ out of that scan. Run `./scripts/lint.sh demo` /
# `./scripts/format.sh check demo` directly to see its findings.
*/demo/*
